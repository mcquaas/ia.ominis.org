# Ominis Health LLM - Data Privacy & Residency Policy

This document describes how data is handled, stored, and processed within the Ominis Health LLM system.

**All data storage and processing occurs 100% within Mexico. No data is transferred outside the country.**

## Overview

Ominis Health LLM is designed with **100% Mexico data residency** as a core requirement. All data storage, processing, and AI inference occurs within AWS's mx-central-1 region (Mexico). The system makes no external API calls to AI services outside of Mexico.

### Key Principles

1. **100% Mexico Residency**: All data stays in Mexico
2. **Self-hosted LLM**: Ominis-2.0 on EC2 in Mexico - no external AI APIs
3. **Local Embeddings**: Generated locally, no external calls
4. **No User Data Storage**: Queries are transient only
5. **No Cross-border Transfers**: Zero data leaves Mexico

## Data Classification

### Data Types in the System

| Data Category | Classification | Sensitivity | Storage Location |
|---------------|----------------|-------------|------------------|
| Health Content | Public | Low | Mexico (S3 mx-central-1) |
| Vector Embeddings | Derived | Low | Mexico (S3 mx-central-1) |
| System Configuration | Internal | Low | Mexico (S3 mx-central-1) |
| User Queries | Transient | Medium | **Not Stored** |
| User Answers | Transient | Medium | **Not Stored** |

### Data Definitions

#### Health Content (Public)
- Source: WordPress/Tainacan public posts
- Content: Health education articles, guides, resources
- Nature: Publicly available health information
- PII: None

#### Vector Embeddings (Derived)
- Source: Generated locally from health content
- Content: Numerical representations of text
- Nature: Mathematical vectors, not human-readable
- Generated by: Local sentence-transformers (no external API)
- PII: None

#### User Queries (Transient)
- Source: End users via chat interface
- Content: Health questions in Spanish
- Nature: Processed in real-time, **not persisted**
- External transfers: **None** - processed by Ominis-2.0 in Mexico
- PII: Potentially (if user includes personal info)

## No External API Calls

### Self-hosted Architecture

Unlike systems that rely on external AI APIs (OpenAI, AWS Bedrock, etc.), this system is fully self-hosted:

| Component | Implementation | External Calls |
|-----------|---------------|----------------|
| Embeddings | sentence-transformers (local) | **None** |
| LLM Inference | Ominis-2.0 on EC2 (Mexico) | **None** |
| Vector Search | In-memory keyword matching | **None** |
| Storage | AWS S3 (Mexico) | **None outside Mexico** |

## User Data Handling

### Query Processing Flow

```
1. User submits question
   └─▶ API Gateway receives request (mx-central-1)
       └─▶ Lambda processes (in-memory, mx-central-1)
           └─▶ Keyword search (local, no external calls)
               └─▶ Ominis-2.0 generates answer (EC2 mx-central-1)
                   └─▶ Response returned to user
                       └─▶ Request data discarded
                           └─▶ NO STORAGE, NO EXTERNAL TRANSFER
```

### User Privacy Commitments

1. **No Account Required**: Anonymous usage
2. **No Query Logging**: User questions are not persisted
3. **No Tracking**: No cookies or user identification
4. **No Analytics**: No third-party analytics services
5. **No External AI APIs**: All AI processing self-hosted in Mexico
6. **Frontend Storage**: Only API endpoint saved in browser localStorage

### Handling Sensitive User Input

If a user includes personal health information in their query:

1. The information is processed transiently in Mexico
2. It is processed by Ominis-2.0 on EC2 in Mexico
3. It is **NOT** sent to any external API
4. It is **NOT** stored in any database
5. It is discarded after the response is generated

**Recommendation**: Users should avoid including personal identifiable information in queries.

## Compliance Considerations

### Mexican Data Protection (LFPDPPP)

The Ley Federal de Protección de Datos Personales en Posesión de los Particulares applies to personal data. This system:

- Does not collect personal data from users
- Stores only public health information
- Processes queries transiently without retention
- Maintains **100% data residency in Mexico**
- Makes **no cross-border data transfers**

### Data Sovereignty

This system is designed for organizations requiring strict data sovereignty:

- All infrastructure in Mexico
- No dependencies on external AI services
- No data transmission outside national borders
- Full control over data processing

### Healthcare Information

The system provides **general health information**, not medical advice:

- Content sourced from public health resources
- No patient-specific data processed
- Clear disclaimer in user interface
- Recommendation to consult professionals

### Network Security

- Ominis-2.0 EC2 runs in private VPC subnet
- Lambda accesses Ominis-2.0 via VPC internal network
- No public internet access from LLM instance
- Security groups restrict access to Lambda only

### IAM Policies

All AWS resources use least-privilege IAM policies:

- Lambda can only read from specific S3 buckets
- No external service permissions (no Bedrock, no SageMaker)
- No public S3 bucket access
- No cross-account access

### Monitoring

- CloudWatch Logs (no PII, 30-day retention, Mexico only)
- CloudWatch Metrics for performance
- No third-party analytics or monitoring
